## 1. 策略代号（先读这一节）

表格第三列统一写 `读 / 写`，代号含义如下。所有判定都在**后端**执行；`GET /api/ui/fields` 返回的是已按当前用户裁剪过的目录，`PATCH` 对每个字段单独鉴权，越权直接 403（不静默丢弃）。

| 代号 | 含义 | 判定口径 |
| --- | --- | --- |
| `SYS` | 系统写入 / 公式 / 规则引擎输出 | 全体角色只读，界面灰显带锁；公式与引擎数值不得被任何生成式模型改写 |
| `BASE` | 航次基础字段 | 读：全员可看。写：按权限矩阵「改航次」行 —— 本人航次 ✓（业务员 / 主管）、本部门他人仅部门主管 ✓、别的部门仅系统管理员 ✓、历史只读航次全员 —、物流管理员 — |
| `OPS` | 卸船作业数据（T06 第 1 组） | 读：全员可看。写：大宗采购部（本人航次或本部门主管）+ 仓储物流部业务员 / 主管（可改任意大宗船作业数据，不含费用）+ 系统管理员；**船抵卸港后才能登记**；历史只读 — |
| `MONEY` | 费用结算（T06 第 2 组） | 读：仅「看金额」✓ 的角色（业务员·大宗采购部、部门主管·大宗采购部、系统管理员），**其余角色接口整体不返回**；写：大宗采购部本人航次 / 本部门主管 + 系统管理员；变更日志只记「已修改」；导出同样裁剪 |
| `SALES` | 成品销售扩展（T07） | 读：全员可看。写：商务海运部业务员（仅本人航次）、商务海运部部门主管（含他人航次）、系统管理员 |
| `META` | 主数据（T01/T02/T03/T08） | 读：全员可看。写：港口 / 泊位 / 船舶维护仅物流管理员 + 系统管理员；新增船舶全员可建；经验航程仅部门主管 + 系统管理员 |
| `LOG` | 应用库日志 / 批次 / 预测结果 | 只读；运行日志（D09）仅系统管理员；靠船计划与库存导入仅物流管理员 + 系统管理员 |
| `ENGINE` | 规则引擎输出 | 一律只读、原样展示；前端与生成式模型均不得重算或改写 |

「无数据」在任何策略下都显示为灰色斜线，绝不显示 0%。CMR 四档色阶、低可信标签、`StatusTag` 的 8 状态在任何皮肤 / 密度 / 视图配置下逐字不变。

## 4. 明确不进字段目录的项

**设计稿专有、规格里不存在**（C2）：船东、优先级 / 加急、ETA 船讯网、ETA 偏差、泊位冲突、船舶动态四值（即将到港 / 在途 / 已批准 / 异常）、审核 / 批量审批、当前状态、更新时间、AIS 数据正常 / 气象服务延迟 / 泊位系统在线。处理原则：能映射的映射到现有字段（业务员 → 负责业务员、合同号 → T05 合同号、更新时间 → D02 最新一条、当前状态 → T04 船舶状态），不能映射的列入 Q1 走规格变更；一律不自创字段或状态。

**一期不接入**：AIS / 船讯网 / 气象自动数据、实时数据流、泊位冲突检测、容量指标（CMR 以外）、审批动作、综合评分、风险标记体系、成本决策。界面措辞写「数据更新于 HH:MM」，不写「实时」。
