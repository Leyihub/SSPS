**本机验证 `AuthorizationSDK` 的结论（回答手册 §8 第 2 条）**：SDK 可用，`members.list(bizID)` 用我们建的角色 ID（`ssps_admin` 等）可以查到成员，`bizID` 就是 `--role-id`；**但返回形状与代码假设不符**（见 3）。`roles` 在请求头里放的是 ID 还是名称仍未确认（本机请求头是手填的）。

## 5I. 阶段 7：前端在本机用真实数据逐页验证（2026-11-06）

**做法**：`npm run build:client` 和 `preview:build` 都能构建（类型检查通过）。本机起真实后端（`SSPS_STORE=real`、连开发库），用一个小代理（只在本机临时脚本里，不进仓库）静态托管 `dist/preview`、转发 `/api` 并注入登录身份（`ssps_admin`）和 CSRF；用 Playwright 1.64 的无头 Chromium 以 1920 宽逐页截图，同时收集控制台报错和失败接口。**没走妙搭 AppContainer**（它依赖平台接口，本机跑不起来），所以平台内的表现、真实网关传来的角色，仍要等发布后验证。内置浏览器窗格太小、截图被截断，不适合做这个。

**已验证（真实数据）**：工作台、智能提问（P11）、智能发船预测（P02）、港口容量日历（P06）、预测详情、航次列表、靠船计划（P07）、主数据（P08）、数据质量（P09）、系统管理（P10）共 10 页全部渲染，**没有控制台报错、没有 4xx/5xx 接口**。日历 11-16 起灰色斜线「无数据」不是 0%，CMR 色阶、近 15 天 / 15 天后两条路径的标签、预测详情的 S1 五步溯源区块、备选方案「低可信」标签、30 天容量条都按原型基线显示。交互走通：智能发船预测页点「预测」出推荐方案 + 备选方案；智能提问页输入「烧结粉矿 秦皇岛→德信 3万吨 11月26日前」解析出物料、货量、航线、截止日，并给出库存趋势、断料日 1/6、最晚到港 1/3、以约定截止日 11/26 为准的结论。

**发现并修好的 4 处问题**：
- **日历右侧「当日在港和预抵的船」表把整页撑出横向滚动**（页面 2324px 宽）：真实货物名一条里可能写好几种货，原型的虚构短名字没暴露。货种列限宽 + 省略号（悬停看全文），表格在卡片内可滚动。
- **中文文件名乱码**（靠船计划页的批次文件名、智能提问页的「已导入」都显示成 `å¾¼å…...`）：busboy 把 multipart 文件名按 latin1 解码。`parseUpload` 里还原，只在「全是 latin1 字符且重新按 UTF-8 解码没有无效字符」时才改。用 Node 的 FormData（和浏览器一样按 UTF-8 发）上传真实文件，文件名原样存回。注意：Windows 上 Git Bash 的 curl 会把文件名按 GBK 发出去，拿它测会误以为没修好。
- **系统时间差 8 小时 / 「今天」在北京时间 00:00–08:00 会算成昨天**：数据库适配器把「YYYY-MM-DD HH:mm」当 UTC+8 存取，但各服务默认时钟用 UTC 生成这种字符串。表现是同一批导入在靠船计划页显示 15:33、在同步日志里显示 07:33，预测运行时间也早 8 小时；更严重的是 `today` 取 UTC 日期，北京时间零点到早上 8 点之间日历和预测会整体错一天。新增业务时钟 `bizNow()`（`server/lib/dates.ts`，UTC+8），五个服务、快照、预测、健康检查默认都用它，并有测试（模拟 UTC 16:30 = 北京次日 00:30）。**线上服务器时区未知，这个修法与服务器时区无关。**
- **页面加载慢**：快照加载的七条查询改并行（日历 19.5 秒 → 10.8 秒）；库存摘要接口不再读几千行逐日序列（只读错误行）。本机到开发库每条 SQL 仍要 1.4 秒左右，所以日历、库存页在本机仍要 10 秒上下；这是环境延迟，线上预计小得多，但**没有线上数据**。

**留着没动**：开发库里 BP-20261106-01/-02、IV-20261106-01/-02 是更早导入的批次（其中 -02 是用 curl 测试时文件名乱码的批次，无害）；当前批次是 BP-20261106-03、IV-20261106-03。旧规则下产生的 6 条「靠船计划日期异常」数据质量问题已删。

**未验证**：妙搭 AppContainer 内的表现；真实网关传来的角色是 ID 还是名称；其他角色（业务员、部门主管、物流管理员）看到的页面差异（只用了 `ssps_admin`）；航次列表 / 航次详情 / 工作台有航次数据时的样子（开发库航次表是空的，要等阶段 8 迁移）；手机宽度；写入类按钮（采纳方案、录入航次等）在页面上的点击（后端写入已在阶段 3、4 验证）；视觉上与原型的逐像素对照（我看了截图，没有做对照工具）。
