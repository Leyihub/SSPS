# 人员映射：给本机 AI 的提示词（按姓名查飞书 ID）

> 2026-11-07。背景：历史迁移要把原表里的业务员、合同执行人员、创建人等**姓名文本**换成飞书用户（open_id）。原表里有约 100 个不同姓名（含非人名的杂项），Leyinet 已给 lark-cli 开了通讯录权限，交给本机 AI 按姓名搜。
> **结果含员工姓名和飞书 ID，只留在本机，不要提交进任何仓库、不要发到第三方服务。**

## 0. 可直接粘贴给本机 AI 的提示词

```
你在 Leyinet 的本机，用 lark-cli 的通讯录能力（lark-contact 技能，user 身份）按姓名查飞书员工。

输入：「迁移-人员映射模板.csv」，列为：姓名（原表写法）、出现次数、出现在哪些列、对应的飞书账号、备注。约 100 行。
任务：对每一行的「姓名」，运行  lark-cli contact +search-user --query "<姓名>" --as user  ，判断结果，把以下列填回去，输出「迁移-人员映射-已查.csv」（UTF-8 带 BOM）：
  - 状态：唯一命中 / 多个候选 / 未找到 / 疑似非人名
  - 飞书 open_id（以 ou_ 开头；仅「唯一命中」时填）
  - 飞书显示名、部门、邮箱
  - 候选列表（「多个候选」时，每个候选写：显示名｜部门｜open_id，用「；」分隔，最多 5 个）
  - 备注

判定规则：
1. 姓名完全一致且只有一个结果 → 唯一命中。
2. 有多个同名结果 → 多个候选，不要擅自选第一个；如果其中只有一个在「德信 / IMIP / 大宗 / 海运 / 物流 / 采购 / 仓储」相关部门，可以在备注里写「推荐」，但状态仍是多个候选，由 Leyinet 确认。
3. 搜不到 → 换写法再试一次（去掉空格、繁简体、只用姓名最后两个字加全名搜），仍然没有就是未找到。
4. 「出现在哪些列」里带「储运」的列，值可能不是人名（岗位、部门、备注）。看起来不是人名的（含数字、斜杠、英文单词、超过 4 个汉字、含「组」「部」「科」等），状态写「疑似非人名」，不要去搜。
5. 一个单元格里写了多个人（用 、 , / 分隔）的，原表模板里已经拆开成一人一行，按行处理即可。
6. 不要在输出里编造任何 ID；没查到的格子留空。

红线：只读查询，不要发消息、不要加好友、不要改任何飞书数据；不要把姓名和 ID 发到 lark-cli 之外的任何服务；不要把输出文件放进 git 仓库目录。
最后给一段统计：唯一命中 / 多个候选 / 未找到 / 疑似非人名各多少行，并把后三类逐条列出，等我确认。
```

## 1. 输入文件

`迁移-人员映射模板.csv`（由 `scratchpad/people.ts` 从真实 Excel 的人名列抽取，100 行；已含出现次数，出现次数高的优先处理）。Leyinet 会把文件交给本机 AI；本机 Claude Code 如需重新生成，运行同名脚本。

## 2. 之后怎么用（给本机 Claude Code）

「已查」表由 Leyinet 复核后：①「多个候选」「未找到」逐条确认；②「疑似非人名」的值决定怎么处理（多半是迁移时直接放进备注字段，不映射为人员）；③确认后的映射作为迁移写入的配置文件（只留本机），写入 T04/T05 人员字段时按它替换。**映射表没有交回之前，迁移的正式写入不能做；模拟阶段（dry-run）不受影响。**
