# 港口主档扩充：给其他 Agent 的任务书（剩余 406 种写法）

> 2026-11-06 生成。背景：SSPS 历史迁移的试跑里，装港 / 卸港 / 装货港共 734 种原始写法，前 100 种已由本机 Claude Code 判定（见 `迁移-港口写法-前100已填.csv`），自动归并后还剩 **406 种写法、732 次出现**没有对上港口主档。这份文档交给另一个 Agent，把剩下的判定出来。
> **不要把含真实业务数据的 CSV 提交进任何仓库**；处理完把结果文件交回 Leyinet。

## 1. 你拿到的文件（Leyinet 会一起提供）

| 文件 | 内容 |
| --- | --- |
| `迁移-剩余未匹配港口写法.csv` | **要你处理的清单**。406 行，按出现次数从多到少。列：序号、港口写法、出现次数、出现在哪些表、自动归并键、同键写法数；后面 8 列（处理方式、标准港口英文名、已有港口编码、中文名、国家、性质、把握、说明）**是你要填的** |
| `迁移-港口主档现有清单.csv` | 主档里**已经有**的 264 个港口（含编码、国家、性质、别名）。判定前先对照它：港口已存在就并入，不要重复新增 |
| `迁移-港口写法-前100已填.csv` | 前 100 种的已填结果，**当作判定风格的样例**，列和你要填的一样 |

## 2. 任务

对「剩余未匹配港口写法」里的每一行，决定它属于下面哪一类，并填完同一行的其余列：

1. **并入已有**：这个写法指的是主档里已经有的某个港口（可能只是多写了国家、多了 `PT.` / `PORT` / `，印尼`、中英文混写、拼写变体）。填「标准港口（英文）」和「已有港口编码」，必须和主档现有清单里的写法**逐字一致**。
2. **新增**：确实是主档里没有的港口。填标准英文名、中文名、国家、性质（见 §3）。
3. **新增（信息待补）**：能判断它是一个港口 / 码头，但查不到它在哪、属于哪个国家（典型是印尼公司的自用码头，写法形如 `PT.XXX PORT`、`JETTY XXX`、`CV.XXX PORT`）。只填标准英文名和你能确定的部分，国家写「待确认」或「印度尼西亚（待确认）」，把握填「低」。
4. **忽略**：不是具体港口——只写了国家（「澳洲」「美国」「USA」）、泛指一片区域（「Far East Russian Ports」）、或占位符（「/」「-」）。
5. 一个写法里其实含**多个港口**（`A+B`、`A/B`）：在「说明」里写明拆成哪几个，「处理方式」按第一个港口填。

**先利用「自动归并键」**：同键的写法大概率是同一个港口，先按键分组判定，再回填到每一行，同组的写法填一样的标准名。

## 3. 填写规则（沿用已定的约定，不要另起一套）

- **标准英文名格式**：大写，`名称, 国家`（如 `TALIABU, INDONESIA`、`HAY POINT COAL TERMINAL, AUSTRALIA`）。码头 / 锚地要保留类型词（`TERMINAL`、`ANCHORAGE`）。公司自用码头国家不确定时只写 `XXX PORT`（去掉 `PT.` / `CV.` 前缀）。
- **中文名**：知道通行中文名才填（如 莫比尔、温哥华）；音译没把握、不确定的写「待补」，**不要编**。
- **国家**：用中文（印度尼西亚、澳大利亚、俄罗斯……）。
- **性质**：印尼境内的港口 = **内港**；其余国家 = **外港**。
- **前缀含义**：`PT.` / `CV.` 是印尼公司名前缀，说明那家公司在印尼，写法里出现过任一带 `PT.` 的变体，就可以把同一缩写的所有写法归为一个印尼公司码头（国家仍标「（待确认）」）。
- **把握**：高 = 港口身份和位置都有可靠依据；中 = 身份有把握，位置 / 同一性有推断；低 = 只能确定是个码头，细节待业务确认。
- **「说明」**里写依据（例如「Hay Point 煤炭码头，昆士兰」「写法里带 PT.，应为印尼公司码头」），低把握的写清楚需要业务确认什么。
- **不要**把省 / 州 / 国家当成港口（`ACEH` 是省，已按「新增、把握中」处理并注明需要确认具体港口，类似情况照此办理）。

## 4. 红线

1. **不得编造**。查不到的港口，如实写「新增（信息待补）」+ 把握「低」，比猜一个国家强。判定地理位置时可以联网搜索，但「说明」里要写依据；搜不到就写搜不到。
2. 不要改动主档现有清单里已有港口的名称和编码；只能追加别名。
3. 不要改「出现次数」「出现在哪些表」「自动归并键」这几列。
4. 把握为「低」的行**不得**填具体国家（只能写「待确认」「印度尼西亚（待确认）」）。
5. 全部是本地文件处理，不要把文件内容发到任何第三方服务；联网搜索只搜港口名，不要上传文件。

## 5. 交付

- 填好的 `迁移-剩余未匹配港口写法-已填.csv`（UTF-8 带 BOM，列与输入一致）。
- 一段统计：并入已有 / 新增 / 新增（信息待补）/ 忽略 各多少行、覆盖多少次出现；把握为「低」的清单（交给业务确认）。
- 自检：①所有「并入已有」的标准名都能在主档现有清单里逐字找到；②同一归并键的写法，标准名是否一致（不一致的在说明里解释）；③「忽略」的行是否确实没有具体港口。

## 6. 之后怎么用（给 Leyinet / 本机 Claude Code）

填好的表格回到本机后：把「并入已有」的写法加到已有港口的别名，「新增」的写进 T01 港口主档（带国家、性质），「忽略」的写法进忽略名单，然后用 `scripts/migrate-dryrun.ts --ports <主档 json> --ignore <忽略名单 json>` 重跑试跑，核对「未匹配」是否降到只剩把握为「低」的那些。
