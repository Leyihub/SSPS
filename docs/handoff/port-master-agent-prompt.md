## 2. 任务

对每一行，复核「处理方式」及后面的列，属于下面哪一类：

1. **并入已有**：这个写法指的是主档里已经有的某个港口（多写了国家、多了 `PT.` / `PORT` / `，印尼`、中英文混写、拼写变体）。「标准港口（英文）」必须和主档现有清单里的写法**逐字一致**。
2. **新增**：确实是主档里没有的港口。填标准英文名、中文名、国家、性质（见 §3）。
3. **新增（信息待补）**：能判断它是一个港口 / 码头，但查不到它在哪、属于哪个国家（典型是印尼公司的自用码头，写法形如 `PT.XXX PORT`、`JETTY XXX`、`CV.XXX PORT`）。国家写「待确认」或「印度尼西亚（待确认）」，把握填「低」。
4. **忽略**：不是具体港口——只写了国家、泛指一片区域、占位符、船名、公司名。
5. 一个写法里含**多个港口**（`A+B`、`A/B`、`A and B`）：说明里写明拆成哪几个，「处理方式」按第一个港口填；后面的港口如果主档没有，请单独追加一行（序号留空，写法留空，处理方式「新增」）。

**先利用「自动归并键」**：同键的写法大概率是同一个港口，先按键分组复核，再回填到每一行，同组的写法填一样的标准名。

## 3. 填写规则（沿用已定的约定，不要另起一套）

- **标准英文名格式**：大写，`名称, 国家`（如 `TALIABU, INDONESIA`、`HAY POINT COAL TERMINAL, AUSTRALIA`）。码头 / 锚地保留类型词（`TERMINAL`、`ANCHORAGE`）。公司自用码头国家不确定时只写 `XXX PORT`（去掉 `PT.` / `CV.` 前缀）。
- **中文名**：知道通行中文名才填；音译没把握、不确定的，保持与英文名一致或写「待补」，**不要编**。
- **国家**：用中文。
- **性质**：印尼境内的港口 = **内港**；其余国家 = **外港**。
- **前缀含义**：`PT.` / `CV.` 是印尼公司名前缀，说明那家公司在印尼（国家仍标「（待确认）」）。
- **把握**：高 = 港口身份和位置都有可靠依据；中 = 身份有把握，位置 / 同一性有推断；低 = 只能确定是个码头，细节待业务确认。
- 「说明」里写依据；本机判定里带「【模拟】」前缀的是猜测，查实后请去掉前缀并写依据。
- **不要**把省 / 州 / 国家当成港口。

## 4. 红线

1. **不得编造**。查不到的港口，如实写「新增（信息待补）」+ 把握「低」，比猜一个国家强。联网搜索时「说明」里要写依据；搜不到就写搜不到。
2. 不要改动主档现有清单里已有港口的名称和编码；只能追加别名。
3. 不要改「出现次数」「出现在哪些表」「自动归并键」这几列。
4. 把握为「低」的行**不得**填具体国家（只能写「待确认」「印度尼西亚（待确认）」）。
5. 全部是本地文件处理，不要把文件内容发到任何第三方服务；联网搜索只搜港口名，不要上传文件。

## 5. 交付

- 复核后的 `迁移-剩余未匹配港口写法-复核后.csv`（UTF-8 带 BOM）。
- 一段统计：同意 / 已改各多少行（逐条列改动）、仍查不到的清单（交给业务确认）。
- 自检：①所有「并入已有」的标准名都能在主档现有清单里逐字找到；②同一归并键的写法，标准名是否一致（不一致的在说明里解释）；③「忽略」的行是否确实没有具体港口。

## 6. 之后怎么用（给 Leyinet / 本机 Claude Code）

复核后的表格回到本机后：以它为准更新港口主档扩充配置，把「并入已有」的写法加到已有港口的别名，「新增」的写进 T01 港口主档（带国家、性质），「忽略」的写法进忽略名单，再用 `scripts/migrate-dryrun.ts --ports <主档 json> --ignore <忽略名单 json>` 重跑试跑，核对数字没有意外变化。
