# 安全与权限审查记录（W52，2026-11-05 云端部分）

范围：云端能审的代码层面。真实平台上的权限（四个测试账号逐项验证、Base 对业务角色不开放、RLS 实测）要在本机做，见任务书 W15、W52。

**已查并处理**

1. 未知异常的响应带堆栈和原因（脚手架原有行为）→ 生产环境不再返回，只写服务端日志；测试覆盖。
2. 前端导出 CSV 的单元格以 `= + - @` 开头会被 Excel 当公式执行 → 导出时补前导单引号；测试覆盖。
3. `.xlsx` 读取器对压缩条目没有解压上限（压缩炸弹）→ 单条目解压上限 50MB；上传本身已限制 10MB；测试覆盖。
4. 定时任务入口：原先设计的「内部令牌 + HTTP」会被控制器的 `@NeedLogin()` 拦住，也多一个对外暴露的密钥入口 → 已改为平台自动化触发器（后端内部执行），没有对外令牌接口。
5. 身份兜底：内存实现对未知用户给「业务员 · 大宗采购部」，真实模式不再使用；没有 SSPS 角色、查不到部门的用户一律 403。
6. 权限矩阵由代码生成并有测试核对一致（`docs/handoff/permission-matrix.md`）。

**已查、无问题**

- SQL 全部走 Drizzle 参数化，没有字符串拼接；JSON 过滤用参数绑定。
- 航次基础字段、结算、销售扩展的写入都有字段白名单，用户请求体里的多余字段会被拒绝或忽略。
- 前端不含 App ID / App Secret；没有 `eval`、`innerHTML`（只有脚手架图表组件里一处静态主题样式的 `dangerouslySetInnerHTML`）。
- 金额字段对无权限用户整体不返回，变更日志里只显示「已修改」。
- 幂等键是客户端生成的 UUID，结果只对知道键的人可见；不构成越权读取。

**需要在真实环境确认**

- 四个测试账号逐项对照权限矩阵验证（W15）。
- Base 对业务角色不开放；T04、T10、T09a、T09b、T08 的系统写入字段对非应用角色只读（建表清单第 356 行）。
- 应用库 RLS：`anon` 已移除读权限（002/003），用匿名连接实测一次读不到。
- 触发器回调入口（`/innerapi/automation/invoke`）只接受平台内网来源——平台能力，但要确认没有被公网暴露。
