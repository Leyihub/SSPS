# 外部评审第二轮核对记录（2026-11-05）

评审方：Gemini（第二轮，七角色分域评审）。核对方式：逐条对照评审包、规格文件和原型代码；涉及库存消耗模拟表的结论，用会话附件里的真实文件复算（只记统计数，文件不入库）；靠船计划和船舶动态表的统计无法复算，标「未核实」。

## 1. 不成立：与材料不符或材料里根本没有

1. DATA-01「库存表列结构与 D12 不符、规格里有『到货量 / arrival_qty』」：D12 规格是「批次号、库存日期、品名、物料类型、日耗、库存、可用天数」，与真实表头「导入日期、库存日期、品名、物料类型、日耗、库存、可用天数」一致；规格里没有「到货量」列。
2. ENG-03「没有过滤发船日已过去的窗口」：引擎 `feasible()` 已剔除「窗口末日 − P80 早于今天」的候选。「最早发船日比建议发船日还早」：系统没有「最早发船日」这个输出。
3. ENG-02 第 2 点「备选会取远端 5% 的高风险窗口」：备选必须满足余量 ≥30%（`okB` 里的 `qualify`），不会取 5% 的窗口。
4. ENG-05「10.3 节 DEGRADED 伪代码」「默认 10~13 天兜底」「berthPlanStale」：评审包里都没有。缺航程规则时，原型是拦截并提示先补经验航程，不是兜底；「低可信」只表示候选窗口数据不完整，与样本数无关（样本数决定的是「经验值 / 统计值」标签）。
5. ENG-06「T04 只有单选 status、没有取消字段」：取消是 T04 的「异常标记」；「漏填离装港没有提醒」：已有「待补节点」待办和数据质量问题。
6. SEC-01「K11 四个角色是管理员 / 大宗采购部 / 非大宗业务部门 / 只读访客」：实际是业务员、部门主管、物流管理员、系统管理员。「D09 的 before_json 存了金额」：D09 是同步运行日志，没有这些字段。「T05 有到岸单价」：该列整列为空，已删除。
7. DATA-03 德信池判定搞错：它把 L2、L5 当成池内，把 F3–F5、F7、F9–F11、L4、L8 当成池外。按它自己列出的 98 行分布重算：池内 84 行，池外只有 L2、L3、L5 共 14 行。
8. DATA-05「T04 没有船次号」：T04 第 4 列就是船次号。「T08 经验值会被统计值覆盖」：两组分开存，公式只决定用哪一组。「大宗卸船明细迁进 T05」：规格写的是迁到「综合物流报表」，不进 T05。「D05 没记库存批次」：已有。
9. QA-02「T04.voyage_type 展示名写成内贸 / 外贸」：没有这个字段，内贸 / 外贸是「业务属性」的枚举。「T06 / T07 没有写接口」：A14、A15。「plan_mode 两种写法」：规格里没有 plan_mode。
10. PROD-01「品名只硬编码 9 个」「1/3焦煤会被焦煤截胡」：原型从库存表动态取全部品名，并取最长命中。
11. 疑虑 2「8 万吨船会把小泊位算进分母」：锁定规则 3 正是只计容量 ≥ 货量的泊位，原型也这样做。
12. 第四部分「待确认事项只剩 1 个未勾选项」：评审包里有 119 个未勾选项，它引用的那条原文不存在；它推荐的泊位映射包含 L1、L9、L10、L15、LN1–LN3 等池外泊位。
13. 问题 1「泊位余量率的分子是整船吨数」：CMR = 空闲泊位数 ÷ 能装下的泊位数，按泊位个数算，不按吨数。
14. ARCH-01「第 4 步回写 D01–D03 镜像」：D01–D03 是 ETA 修订、节点日志、靠船计划批次，不是镜像表。

## 2. 成立：用真实库存表复算过

1. 37 个品名里有 33 个在模拟期内降到 0 及以下，其中 6 个先降到 0、几天后因已排定到货回升、过一段时间再次耗尽。按现在「首次降到 0 即断料日」的规则，这 6 个品名的排船目标会被锁在近期一个已经来不及的短缺口上。
2. 各品名模拟终点有 13 个不同日期；日耗为 0 的有 57 行；错误值行按「库存」列数是 248 行（它说 252，口径差异）。
3. 原表「可用天数」不是当天库存 ÷ 当天日耗，第一行明显是按次日日耗折算的，与原型算法不同。

## 3. 成立：设计问题，建议采纳

技术类（写代码时由技术负责，不需要业务决定，已写进规格）：

1. 写入一致性：写飞书成功、回写镜像或写日志失败时要能补偿；所有写请求带幂等键，重试不重复写；同步事件晚到不得覆盖更新的回写值。
2. 靠船计划整表覆盖不是原子的：改为新批次完整写入后再切换「当前批次」，中途失败时预测仍用上一批。
3. 迁移归并：「船名 + 到港日」会把跨零点、漏填实际到港的拼船拆开（它称 22 组，未核实）；改为同船名、到港日相差不超过 N 天的进确认清单。历史副本去重键不再含到港日。
4. 纯日期和带时分的时间比较：同一天内不算倒置。
5. 时序校验只针对本次改动的节点，历史数据里已有的倒置不拦截无关的保存。
6. G1 迁移验收补四项：货量守恒、子表无孤儿、分层抽样、迁移可重复执行。
7. G2 需要先从德龙版导出并冻结 20 个用例的输入和结果，否则无法对照。

需要业务决定（已写进 `docs/open-questions.md`「外部评审第二轮」一节）：短缺口回弹、库存提问的推荐方案顺序、金额字段在多维表格端的可见范围、物资备件船的航程样本顺序、大宗经验航程表、M1 范围调整。

## 4. 成立但已知或低优先

- 大宗航程样本极少（现表 643 行只有 21 行有离装港时间，历史副本没有这一列，已核实列结构）：M1 已安排业务员提交首版经验航程，需要提前到开工前。
- 语音输入在飞书里不可靠、一船多物料、缓冲天数：已在待确认事项里。
- 发船日按「窗口末日 − P80」：按 P50 船会早到 P80−P50 天，这是「按 P80 反推最晚到港日」的设计取舍，Leyinet 评审 P02 时已确认这种表述。
- 远期路径只按航次的到港窗口计重叠，不算卸货天数：锁定规则 4 的口径，记为疑虑。
- 「L12A」不在 23 泊位池内，不影响计算；如果 IMIP 把 L12A 的船记成 L12，L12 会被高估为占用，低优先。
