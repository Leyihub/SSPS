# 字段组、岗位授权与接力规则

2026-11-16 Leyinet 确认（船舶动态业务体系重构，方案见 `docs/handoff/vessel-dynamics-rebuild-plan.md`）；2026-11-17 原型评审通过后写入规格。本文是修改权限的规格依据，取代「按航次归属判断能不能改」的做法。

状态：**计划中，代码尚未实现**。`docs/handoff/permission-matrix.md` 由代码生成，在后端按本文实现之前仍是旧口径，不要手改。

## 1. 岗位

1. 岗位 = 平台角色 + 飞书部门，共 8 个：业务员（大宗采购部、商务海运部、仓储物流部）、部门主管（三个部门）、物流管理员、系统管理员。
2. 物资备件的业务员在组织架构里属于商务海运部（2026-11-06 确认）。
3. 责任清单里的「大宗综合」不新增角色，由部门主管 · 大宗采购部承接滞期费与速遣费的结算（2026-11-16 确认）。
4. 一个人有多个平台角色时取权限最高的；没有任何 SSPS 角色的用户一律 403。这两条不变。

## 2. 字段组

全部字段来自 `docs/schema/` 现有定义，不新增字段。每个字段只属于一个字段组。

| 组 | 名称 | 包含的字段 |
| --- | --- | --- |
| G01 | 标识与航线 | T04：业务类型、业务属性、船次号、船舶、承运方、船方航次号、装港、卸港、第二卸港、最终目的港、负责业务员、所属部门 |
| G02 | 货物与合同 | T05 除明细编号、航次以外的全部字段 |
| G03 | 计划时间 | T04：受载期始 / 止、计划抵装港、计划离装港、计划抵卸港窗口始 / 止 |
| G04 | 外港侧实际节点 | T04 实际节点中不在本港的那一端（见第 3 条） |
| G05 | 预计到达修订 | T04：当前 ETA（卸港） |
| G06 | 本港侧节点与泊位 | T04 实际节点中在本港的那一端（见第 3 条）；计划泊位、实际泊位 |
| G07 | 卸船作业 | T06：卸货条款、卸率、允许卸货天数、TURN TIME、卸港水尺吨位、水尺 1–3、汽运量、管带机运量、过磅重量、其他部门运量、倒运车数、X1 管带机车数、跨月船汽运 / 管带机预估、3# / 4# 管带机未运行、交接发出日 / 签回日、德天不用交接、小雨保函、影响卸船因素 / 异常反馈 |
| G08 | 港口费用 | T06：汇率、港务费单价、港务费（USD）、装卸费（USD） |
| G09 | 合同结算 | T06：滞期费率 + 币种、滞期费 / 速遣费（USD） |
| G10 | 销售扩展 | T07：租船方式、海运合同号 |
| G11 | 管理标记 | T04：异常标记、重点关注、审核状态、备注 |
| G12 | 系统与计算结果 | T04：航次编号、船名与 MMSI（查找引用）、本港侧、船舶状态、装港逾期、实际航程、本港等泊、本港作业、总货量、拼船、数据来源、原记录键、历史只读；T05 明细编号、航次；T06、T07 的航次关联；预测引擎的全部输出（D05、D06） |
| G13 | 作业日志 | D15 装船记录、卸船记录 |

3. **实际节点按本港侧分组。** T04 的六个实际节点是：实际抵装港、装港靠泊、实际离装港（装港一端）；实际抵卸港、卸港靠泊、卸港离港（卸港一端）。按 T04「本港侧」公式判断：本港侧 = 装，装港一端三个节点属于 G06，卸港一端属于 G04；本港侧 = 卸，反过来。
4. 「负责业务员、所属部门」是权限判断的依据，归 G01；协作台行内不提供修改，仍在详情页里改。是否收紧为只有主管能改，待确认。

## 3. 默认授权

5. 授权取值有三种范围：**本人航次**（航次的负责业务员是当前用户）、**本部门**（航次的所属部门是当前用户的部门）、**任意航次**。一个格子可以有多个范围，满足任意一个即可。

| 组 | 业务员 · 大宗采购部 | 业务员 · 商务海运部 | 业务员 · 仓储物流部 | 部门主管 · 大宗采购部 | 部门主管 · 商务海运部 | 部门主管 · 仓储物流部 | 物流管理员 | 系统管理员 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| G01–G05、G11 | 本人航次 | 本人航次 | 本人航次 | 本部门 | 本部门 | 本部门 | — | 任意航次 |

| G07 | 本人航次 | — | 任意航次 | 本部门 | — | 任意航次 | — | 任意航次 |

| G10 | — | 本人航次 | — | — | 本部门 | — | — | 任意航次 |

6. 字段组的业务类型范围：G07、G08、G09 只对大宗采购船有效；G10 只对成品销售船有效。
7. G06 的分工（2026-11-16 确认）：大宗采购船在本港的到港、靠泊、离港和泊位由仓储物流部登记；成品销售船由负责业务员（商务海运部）登记。物资备件船暂按成品销售船处理，这一条是推断，待确认。
8. **读权限**：G08 只有仓储物流部（业务员、部门主管）、大宗采购部（业务员、部门主管）和系统管理员可读；G09 只有大宗采购部（业务员、部门主管）和系统管理员可读；其余字段组全员可读。原来单一的「看金额」权限按这两组拆开。
9. 相对旧口径的变化共四处：仓储物流部可登记任意大宗采购船的本港侧节点和泊位；港务费、装卸费、港务费单价、汇率改由仓储物流部填，大宗采购部只读；仓储物流部可以看港口费用（看不到合同结算）；新增作业日志。
10. 授权由系统管理员在「岗位授权」勾选表里调整（存 D14），每次修改留痕。新建航次、主数据维护、导入、系统管理等动作权限不在本文范围，仍按现行权限矩阵。

## 4. 不能通过配置突破的底线

11. G12 任何人不可改。规则引擎输出的数值不得被任何人或任何模型改写。
12. 标了「历史只读」的航次，所有字段组都不可改。
13. G09 的读写只能授予大宗采购部的岗位和系统管理员；G08 的读写只能授予仓储物流部、大宗采购部的岗位和系统管理员。勾选表里其余格子不可勾。
14. 没有读权限的岗位，接口响应里不包含该组字段；变更日志里金额变更只记「已修改」；导出、错误提示同样不带出。
15. 船抵卸港后才能登记 G07、G08、G09；船在港作业期间才能追加 G13。
16. 时间先后校验和状态推导照旧（`status-rules.md`）。

## 6. 接力规则

20. 不新增状态，不新增「接力进度」之类的存储字段，不保留人工船舶动态。「轮到谁、该补什么」由船舶状态加空缺字段现算。下表中「负责人」指航次的负责业务员（其部门主管同样算轮到）。

**大宗采购船（本港是卸港）**

| 状态 | 轮到谁 | 条件与内容 |
| --- | --- | --- |
| 待宣船 | 负责人 | 船舶、合同号、计划抵卸港窗口中为空的项 |
| 未到装港、装港等泊、装港装货 | 负责人 | 计划离装港已到而实际离装港为空：登记实际离装港 |
| 航行中 | 负责人 | 当前 ETA 为空或超过阈值天数未更新：修订 ETA |
| 航行中 | 仓储物流部 | 当前 ETA 在 7 天内而计划泊位为空：填计划泊位；当前 ETA 已到：登记实际抵卸港 |
| 卸港等泊 | 仓储物流部 | 卸港靠泊、实际泊位 |
| 卸港卸货 | 仓储物流部 | 当天没有卸船记录：追加卸船记录 |
| 任意 | 负责人 | 已有实际抵卸港而实际离装港为空：补实际离装港 |
| 已结束（离港 30 天内） | 仓储物流部 | 港务费、交接签回日中为空的项 |
| 已结束（离港 30 天内） | 大宗采购部（负责人、主管） | 滞期费 / 速遣费为空 |

**成品销售船（本港是装港）**

| 状态 | 轮到谁 | 条件与内容 |
| --- | --- | --- |
| 待宣船 | 负责人 | 船舶、合同号、受载期中为空的项 |
| 未到装港 | 负责人 | 计划抵装港已到：登记实际抵装港 |
| 装港等泊 | 负责人 | 装港靠泊、实际泊位 |
| 装港装货 | 仓储物流部 | 当天没有装船记录：追加装船记录 |
| 装港装货 | 负责人 | 计划离装港已到：登记实际离装港 |
| 航行中 | 负责人 | 当前 ETA 为空或超期未更新；海运合同号为空；当前 ETA 已到：登记实际抵卸港 |
| 卸港等泊 | 负责人 | 卸港靠泊 |

21. 物资备件船：本港是卸港时按大宗采购船的规则走，但本港侧节点归负责人、不记作业日志和卸船结算（暂定，待确认）。
22. 「阈值天数」沿用工作台「ETA 多久未更新算超期」的口径（暂定 3 天，待确认）；「7 天」「30 天」为暂定值。

## 7. 视图

23. 一个视图 = 显示的列与顺序、默认筛选、默认排序、密度。存 D13。
24. 视图有四级，后者覆盖前者：系统预置、部门模板、岗位模板、个人视图。部门模板和岗位模板由系统管理员维护；个人视图本人维护。
25. 任何视图只能包含当前用户有读权限的字段；导出按读权限裁剪，不按视图裁剪。
26. 系统预置视图：待我更新（按第 6 节现算）、大宗到船计划、成品发运、物资备件、在港与临港作业、装船进度、费用结算（仅对 G08 或 G09 有读权限的岗位出现）、全部航次。
27. 密度两档：舒适（行高 44px）、紧凑（行高 32px，默认）。密度是独立于皮肤的维度，几何规则不进 `skin.css`。
