## 2. 已知限制与需要人工配置

飞书开放接口不能创建「查找引用」字段。T04 里有 4 个要在界面手工配（每个约半分钟）：

1. `船名`：查找引用，关联字段 `船舶`，引用 `标准船名`
2. `MMSI`：查找引用，关联字段 `船舶`，引用 `MMSI`
3. `装港是否本港`：查找引用，关联字段 `装港`，引用 `是否本港`

## 3. 我核对出来的问题

1. **公式自检没做完**：`本港侧` 依赖 `装港是否本港`，而这个查找引用还没建，所以 `本港侧`、`本港等泊（天）`、`本港作业（天）` 三个公式当时算不出结果。报告里这三项只写了预期值，真正读回来验证的只有 `实际航程（天）`（5.77）和 `拼船`（否）。手工建好 4 个查找引用后，必须重跑一次自检（提示词见 `base-verify-agent-prompt.md`）。
2. **Base 里原本就有 17 张企微历史表**（共 1 万多条记录），不在我们的计划里，也没被动过。需要你确认：它们是你为迁移准备的吗？如果是，迁移脚本可以直接通过接口读这些表，不用再读 Excel，我会据此调整迁移方案。它们含真实业务数据，所以这个 Base 更要坚持只对应用和系统管理员开放。
3. **建表过程中 agent 做过很多试建实验**（试建 T01、自动编号、双向关联、空单选等）。报告只说「新建数据表 10 张」，没说试验用的表和字段有没有清掉。预期 Base 里现在是 17 + 11 = 28 张表，如果多了，就是试验残留，需要清理。
4. **T01 种子数据和计划不一致**：计划写的是中文名「巴浩多比」，agent 写成了「莫罗瓦利（IMIP）」，别名里多了「德信本港」。这可能是 agent 从 Base 里原有的「港口信息表」读来的，如果是，以真实数据为准更好；但页面和自然语言解析里用的是「巴浩多比」，别名里要包含它。请你确认本港的中文名，我再对齐代码里的别名。
5. **高级权限（系统写入字段设为只读）这一步可以取消**：因为 Base 只对应用和系统管理员开放，业务员根本看不到也改不了表格，不需要再设字段只读。
