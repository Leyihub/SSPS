# 兼容表 T09a / T09b 的列对应（A26 实现依据）

实现：`app/server/domain/compat.ts`（行生成，纯函数）、`app/server/modules/admin/compat.service.ts`（整表重写）。列名和顺序取自旧表，和 `base-plan.json` 一致（测试核对）。**旧表没有给出每一列的口径，下面的对应是按列名推断的，标「待确认」的请 Leyinet 对着旧表核一遍**（见 `docs/open-questions.md`）。

**收哪些航次**：T09a（商务海运船舶动态）收成品销售船和物资备件船；T09b（大宗到船计划）收大宗采购船。待确认。**每行**对应一行货物明细；航次没有货物明细时输出一行、货物列留空。所有列都是文本，没有值写空字符串。

## T09a（33 列）

有数据的列：审核（审核状态）、关注（重点关注=「是」）、业务类型、业务属性、序号（本次输出的流水号）、租船方式（T07）、MMSI/IMO（主数据船舶）、船次号、供应商/船名（取船名）、船舶状态、货物类型（物资大类，没有取货物名称）、目的港（最终目的港，没有取卸港）、货量、装港、受载期始/止、预计抵达装港日期、实际到港日期（实际抵装港）、实际靠泊时间（装港靠泊）、逾期（实际抵装港晚于受载期止的天数，没晚留空）、实际离港日期、卸港、预计卸港到达时间（当前 ETA，没有取计划窗口始）、实际卸港到达时间、卸港靠泊时间、销售合同号（货物明细合同号）、海运合同号（T07）、业务员（负责业务员）。

留空的列：卸港代理、创建人、创建时间、最后编辑时间（新模型里没有对应字段，创建/编辑时间可以用飞书记录的创建/修改时间补，待确认）。

## T09b（87 列）

有数据的列：序号、类别（业务属性）、物资分类（物资大类）、合同号、使用单位、供应商、物资类别（货物明细「类别」，目前为空）、货物名称、物资别名、归属事业部、MMSI、IMO、船名、系统船舶动态（船舶状态）、拼船情况（≥2 条明细标「拼船（n）」）、总船重量（航次各明细预计装船重量合计）、干基折算、装货港、预计装船重量、装港重量、溢短装、检测公司、计划到达装港日期、预计开出装港日期、实际开出装港日期、计划到达始/止、实际到达（实际抵卸港）、靠港时间（卸港靠泊）、离港时间（卸港离港）、实际卸船/等泊/共计用时的天和小时（按卸港靠泊、离港、实际抵达的时间差，两位小数）、TURN TIME、卸率/吨、卸港水尺吨位、滞期费率、滞期费（正数）/速遣费（负数取绝对值）、备注、合同执行人员、倒运车数、交接状态 1/2（已发出/已签回 + 日期，「德天不用交接」勾选时写「不用交接」）、跨月船汽运/管带机预估、汽运量、管带机运量、X1 管带机运量/车（取 X1 管带机车数）、月份按离港算（卸港离港的年月）、排靠泊位（计划泊位）、汇率、港务费单价、港务费、装卸费、3#/4# 管带机未运行、1st–3rd 水尺、影响卸船因素/异常反馈、业务员、小雨保函、过磅重量、其他部门运量、业务类型、今日在港（卸港靠泊日期 ≤ 今天且未离港或离港日期 ≥ 今天；只比较日期）、到港日（实际抵卸港，没有取 ETA，再没有取计划窗口始）。

留空的列（新模型没有对应字段）：（人工）船舶动态、价格（到岸价）、卸船进度、可用管带机、X1 管带机吨位、2#管带机未运行、4st 水尺、备注 Keterangan、价格类型、创建人、储运 1–5、公式。

## 刷新方式

按现有行的顺序就地覆盖，多出来的行新增，少了的行删除，表里始终有数据（飞书多维表格没有「先写新表再切换」）。定时任务由平台自动化触发器调用（`app/server/modules/admin/jobs.automation.ts`）：每日 15:50 全量重写；每 10 分钟增量（航次保存后只置「待刷新」标记，没有标记就跳过）。系统管理员也可以在系统管理页手动刷新（`POST /api/admin/compat/refresh`）。标记在进程内存里，重启会丢，由每日全量兜底。
